## 已确认的问题与修复行为

| 问题 | 当前行为 |
| --- | --- |
| 拔出 U 盘后，另一设备复用盘符可能继承缓存中的硬件身份 | 缓存同时记录卷序列号；复用旧 WMI 记录必须与当前卷序列号一致，成功的空查询会清空旧表。 |
| 无可靠 USB 标识时退化为 `DRIVE:E:` | 去掉盘符身份；仅可保存硬件 ID 或卷序列号，无身份设备会被拒绝选择。旧盘符配置启动时显示迁移提示、清除内存中的旧身份，等待重新选盘，原文件保留至用户保存。 |
| 缺少卷序列号的 PNP 设备在缓存刷新时存在、随后又缺席 | 无法验证缓存关联时每次扫描最多追加一次 WMI 查询，避免缓存周期造成锁定抖动。 |
| 一块盘扫描中消失可能使整轮 USB 检查失败 | 每个盘独立捕获枚举期间的异常，其余盘继续检查。 |
| 注入的 `Ctrl+Shift+L` 可以触发解锁 | 键盘钩子检查注入标记，注入事件既不能触发快捷键，也不更新物理修饰键状态。 |
| 蓝牙停启后继续使用旧广播、RSSI、连接状态或句柄 | 停止时清空会话证据并撤销句柄；回调、名称查询、配对刷新和句柄创建完成时校验所属会话。 |
| 蓝牙连接不断更新时，过期 RSSI 仍能无限期保持原距离判定 | 阈值模式按 RSSI 自身时间戳判断过期；超过 20 秒缺少信号即判定缺席，连接不能替代距离测量。 |
| 蓝牙扫描启动失败后不再恢复，停启交错时查询取消令牌与会话不匹配 | 周期重试扫描器；在同一个锁内读取取消令牌和会话编号，旧工作受停止取消及会话校验约束。 |
| 设备列表显示旧 RSSI，解除配对未清除状态 | RSSI 超过 4 秒显示未知；完整配对枚举成功后同步移除已解除配对的状态和句柄。查询失败不被当作成功的空结果。 |
| 大量 BLE 广播导致无上限的名称查询 | 名称查询限制并发数量，支持超时、停止取消和会话失效检查。 |
| 未配对随机地址可保存为设备选择 | 选择和保存阶段拒绝已知不稳定身份，恢复上一个已保存的选择。已配对设备继续由 Windows 的配对信息识别。 |
| 后台旧锁定判断在切换设置后仍执行 | UI 线程应用判断前核对设置快照，过期模式或设备的结果丢弃；后续监控周期使用新设置重新评估。 |
| 覆盖层关键 Windows API 或刷新失败仍报告已锁定 | 检查创建、透明度和窗口定位结果，刷新等待实际执行结果；故障时释放输入资源并报告失败。延迟故障通知核对锁定会话，避免把新会话标为已解锁。 |
| 配置损坏或读取失败静默退回“无自动锁定” | 先读取 `.bak` 并显示恢复提示；主文件和备份均不可读时，明确告知自动锁定停用并打开设置页。只有两者确实不存在才视为首次安装。 |
| 固定临时文件与无大小限制降低配置可靠性 | 文件限制为 64 KiB；使用唯一临时文件、刷盘和替换保存。正常替换保留一代备份，恢复后首次保存保留可用备份。 |
| 保存失败后 UI 保留未提交的设备选择 | 临时字段、列表选择和摘要回滚到已保存设备，避免下一次编辑意外提交失败的选择。 |
| 正常退出会丢弃防抖期间的最后一次编辑 | 在服务释放前提交待处理的有效文本编辑，再停止 UI 计时器。 |

配置信息恢复后需要用户检查并重新保存；程序不会仅因启动时无法读取配置就覆盖原文件或移除已有自启动项。退出时的保存是正常 UI 退出路径的保证，不能保证进程被强制结束或断电时尚未保存的编辑仍被保留。

## 设计限制与原审查结论的边界

蓝牙地址及 RSSI 缺少身份认证属于当前方案的设计限制，不能通过增加缓存检查就变成经过认证的安全凭证。软件没有与随身设备进行挑战响应，也不验证每次广播由配对密钥持有者发出。已配对状态仅改善设备识别和连接状态来源，不能认证同地址广播。USB 的 `PNPDeviceID`、卷序列号同样可被仿造。

覆盖层和键盘钩子提供的是桌面输入拦截：画面依然可见，系统安全桌面、进程终止、其他置顶窗口和高权限程序仍在能力边界之外。需要保护数据时应使用 Windows 自身的锁屏与账户认证。

未签名发布物需要发布者提供代码签名证书才能改变其签名状态。SDK、依赖锁文件和 CI 是构建可重复性与回归检查的工程改进；缺少它们本身不等同于一个已复现的运行时错误。

在 Windows 上从仓库根目录运行：

```powershell
dotnet --version
dotnet restore ProxiLock.csproj --locked-mode
dotnet build ProxiLock.csproj -c Release --no-restore
dotnet run --project tests/ProxiLock.Regression -c Release
```

回归入口是 `tests/ProxiLock.Regression/ProxiLock.Regression.csproj`。它以断言和失败退出码验证可隔离的服务逻辑；不能以主工程没有测试却返回成功的 `dotnet test` 结果代替。测试不会替代真实硬件上的蓝牙进出范围、USB 热插拔、多显示器变化和正常退出验证。

`global.json` 将 SDK 约束在 `10.0.302` 所属功能区间，并允许后续补丁；CI 应读取该文件安装 SDK。项目版本由 `ProxiLock.csproj` 的版本属性和 `app.manifest` 中的 `assemblyIdentity` 共同描述，发布时需保持一致。

更新 SDK 或 NuGet 依赖时：

1. 安装目标稳定 SDK，并修改 `global.json` 中的版本；不要只修改 CI 的 SDK 版本。
2. 若更新依赖，同时修改对应项目的 `PackageReference`。
3. 明确解除本次还原的锁定并重新计算锁文件：

   ```powershell
   dotnet restore ProxiLock.csproj --force-evaluate -p:RestoreLockedMode=false
   dotnet restore tests/ProxiLock.Regression/ProxiLock.Regression.csproj --force-evaluate -p:RestoreLockedMode=false
   ```

4. 检查锁文件中的版本和来源变化，再运行正常的锁定还原、Release 构建和回归命令。一并提交项目文件、`global.json` 和产生变化的锁文件。

不要为绕过版本不一致而长期关闭 `RestoreLockedMode`。工程使用的 NuGet 源由根目录 `NuGet.config` 明确指定。
